01 Residual Connection（残差连接）

1.为什么需要残差连接

问题： 深层网络中激活值和梯度逐层衰减

例子（10 层 Linear + ReLU，无残差）：

10 层后激活标准差从 1.0 衰减到 0.0166，只剩 1.6%。


衰减的原因：

每层 Linear + ReLU ：

操作 对方差的影响
Linear Kaiming 初始化下，方差大致保持不变
ReLU 把负半轴置零，方差减半

所以每层标准差乘约：
$$\sqrt{0.5}≈0.707$$

10 层后：
$$1.0\times0.707^{10}≈0.0166$$

呈指数衰减


衰减的后果：

  • 前向：激活值逐层变小 → 原始信息几乎丢失
  • 反向：梯度也逐层变小 → 前面层几乎学不动

反向传播有链式法则：

$$\frac{\partial loss}{\partial x_0}=\prod_{l=1}^{L} \frac{\partial x_l}{\partial x_{l-1}}·\frac{\partial loss}{\partial x_L}$$

每层乘一个雅可比矩阵，如果每层导数小于 1，连乘后指数衰减。

参数更新公式：

$$w_{new}=w_{old}-\eta·\frac{\partial loss}{\partial w}$$

每往回传一层，梯度乘一个导数，如果梯度很小，将会导致前面几层几乎学不动，只有最后几层在学，即梯度消失。


直觉理解：传话游戏

前面的层就像传话游戏里最早的那个人，收到的信号太弱，无法有效学习


2.怎样进行残差连接

残差核心思想

不让网络直接学目标输出，而是学“在输入基础上需要改变多少”，最后把输入加回去。

$$y=x+F(x)$$

参数说明：

$x$：原始输入，直接加到输出
$F(x)$：子层学到的调整量
$x+F(x)$：原始信息 + 调整量

假设理想输出是$H(x)$：

$$y=x+F(x)=H(x)$$

所以：

$$F(x)=H(x)-x$$

$F(x)$是“理想输出和输入之间的差”，这个差就叫残差（residual）。


残差如何解决梯度消失

没有残差的梯度：

$$x_{l+1}=F_l(x_l)$$

反向传播：

$$\frac{\partial x_L}{\partial x_0}=\prod_{l=0}^{L-1}\frac{\partial F_l}{\partial x_l}$$

有残差的梯度：

$$x_{l+1}=x_l+F_l(x_l)$$

反向传播：

$$\frac{\partial x_{l+1}}{\partial x_l}=I+\frac{\partial F_l}{\partial x_l}$$

多层展开：

$$\frac{\partial x_L}{\partial x_0}=\prod_{l=0}^{L-1}(I+\frac{\partial F_l}{\partial x_l})$$

这个连乘里，至少有一条路径是全是$I$相乘：

$$I·I···I=I$$

梯度可以沿着残差连接直接回传，不需要经过任何$F_l$的导数

两条路径并存：

  • 恒等路径：梯度原样回传，不衰减
  • F 路径： 梯度经过子层，可能衰减或放大

即使 F 路径的梯度很小，恒等路径也能保证梯度不完全消失


残差 vs 归一化

机制 作用 解决什么
归一化 控制每层输入的尺度 激活值/梯度不因尺度漂移而爆炸或消失
残差 提供梯度的恒等路径 梯度不因连乘而衰减，深层可训练

02 Transformer Block（Transformer 块）

1.为什么要组装 Transformer Block

问题： 归一化、Attention、FFN、残差都有了，但它们只是零件，需要按正确顺序组装成一个完整的层

一个 Transformer Block 要完成两件事：

  • Attention：让不同 token 互相看，交换信息
  • FFN：对每个 token 独立加工，做非线性变换

每个子层都必须配：

  • 归一化：稳定子层输入的尺度
  • 残差：提供梯度恒等路径

核心问题：这四个组件怎么排？


2.怎样组装 Transformer 块

标准 Pre-Norm Block 的数据流：

四个设计要点：

设计 原因
Pre-Norm 归一化在子层之前，残差主路径干净，梯度有恒等通道
双残差 Attention 和 FFN 各一个，每个子层都有梯度高速路径
Attention → FFN 先交换信息，再独立加工
RMSNorm 比 LayerNorm 更省，效果相当

为什么是 Pre-Norm 而不是 Post-Norm

Post-Norm：

$$y=Norm(x+F(x))$$

问题：

  • 残差路径上的梯度会被 Norm 打断
  • 深层网络（>12 层）训练不稳定
  • 需要非常小的学习率

Pre-Norm：

$$y=x+Norm(F(x))$$

优势：

  • 残差路径更”干净”（梯度可以直接传播）
  • 每个子层的输入分布稳定
  • 深层网络更容易训练
  • 学习率容忍度更高

用梯度解释为什么 Pre-Norm 更稳：

Post-Norm 的反向传播：

$$\frac{\partial y}{\partial x}=J_{Norm}·(I+\frac{\partial F}{\partial x})$$

恒等项$I$被$J_{Norm}$乘了。Norm 的雅可比矩阵会缩放和投影梯度，恒等路径被“污染”。深层连乘$J_{Norm}$，梯度还是可能消失或爆炸。

Pre-Norm 的反向传播：

$$\frac{\partial y}{\partial x}=I+\frac{\partial F}{\partial Norm}·\frac{\partial Norm}{\partial x}$$

恒等项$I$是干净的，没有被 Norm 乘。梯度可以沿残差路径直接回传，不经过任何子层的导数。


为什么是双残差

MiniMindBlock 有两个子层，每个子层都有自己的残差：

路径更短，梯度更稳


为什么 Attention 在 FFN 之前

Attention： 负责“横向”信息交换（token 之间）

FFN： 负责“纵向”特征加工（每个 token 独立）

Attention → FFN：

  • 先让 token 之间交流，再让每个 token 自己消化
  • 符合信息处理逻辑

如果反过来（FFN → Attention）：

  • 先自己消化，再和别人交流
  • 也可以工作，但实验上 Attention → FFN 效果更好
  • 这也是原始 Transformer 的设计，后续模型都沿用

为什么最后要加 Final Norm

Pre-Norm 的残差主路径是干净的：

$$x_{l+1}=x_l+F_l(Norm(x_l))$$

随着层数增加，$x_l$的方差会累积增长（每层都在往上加东西，但没有归一化）。所以 Pre-Norm 模型最后必须加一个 Final Norm，把输出拉回稳定范围，再送进 LM Head。

对比 Post-Norm： 每层输出已经被 Norm 过了，不需要额外的 Final Norm。

参数说明：

$B$：batch size，一次处理几个句子

03 其他组件

1.Tokenizer Encoder：文本 → token ids

模型只认识数字，不认识字符。Tokenizer 的职责就是把自然语言文本映射成整数序列，每个整数是词表里的一个“页码”。

MiniMind 的词表大小是 6400，所以每个 token id 的范围是 0 ~ 6399。


MiniMind 用的 Tokenizer 类型

MiniMind 使用的是 BPE（Byte Pair Encoding）+ ByteLevel 预处理的 tokenizer，使用 HuggingFace Tokenizer 来实现：

组件 配置 作用
模型 BPE 把高频字节对逐步合并成子词单元
Pre-tokenizer ByteLevel，add_prefix_space=False 把文本按字节切分，中文不需要前置空格
词表大小 6400 刻意压缩，避免小模型“头重脚轻”
Decoder ByteLevel，add_prefix_space=True 把 token id 序列还原成文本，恢复自然空格

为什么用 6400 这么小的词表： MiniMind 是 64M 的小模型。如果词表像 Qwen2 一样有 15 万，Embedding 和 LM Head 会占据过多参数，模型“头重脚轻”。6400 的词表让参数集中在 Transformer Block 里。

BPE： 高频组合合并成一个 token，低频组合拆成子词。

ByteLevel： 把输入文本（无论中文、英文、Emoji）全部转换成计算机最底层的 UTF-8 字节序列。


特殊 token

MiniMind 的 tokenizer 里注册了一批特殊 token，用来支撑对话、推理和工具调用。

核心控制 token：

ID token 用途
0 <|endoftext|> 文本结束
1 <|im_start|> 对话/消息开始
2 <|im_end|> 对话/消息结束

推理与工具调用 token：

token 用途
<tool_call> / </tool_call> 工具调用块边界
<tool_response> / </tool_response> 工具返回结果边界
</think> 显式思考过程结束

注意： 推理和工具类的 token 被标记为 special: false，目的是让模型在 SFT 阶段自然学习它们的语义，而不是把它们当作永远不可拆分的硬边界。

Block 堆叠结束后，输出的仍然是 (B, S, 768) 的向量。要预测“下一个 token 是什么”，需要把 768 维向量映射回 6400 个分数：

这 6400 个分数叫 logits。 可正可负，不是概率。分数越高，模型认为这个 token 越可能是下一个。


推理时只关心最后一个位置

因果掩码保证了最后一个位置已经看过前面所有 token 的信息。所以预测下一个 token 时，只需要取最后一个位置的 768 维向量：

MiniMind 源码里的 logits_to_keep 参数：

  • 训练时：logits_to_keep = 0 ,所有位置都算 logits
  • 推理时：logits_to_keep = 1 ,只算最后一个位置的 logits

权重共享：Embedding 和 LM Head 是同一份参数

这两个矩阵形状互为转置，功能也对称： 一个从词表到向量，一个从向量回词表。所以 MiniMind 让它们共享同一组参数。

好处 说明
省参数 6400 × 768 ≈ 4.9M 参数，共享后只存一份
语义一致 同一个 token 的“输入向量”和“输出打分方向”在同一个空间里对齐

MiniMind 默认开启 tie_word_embeddings=True。这是小模型压缩参数的常见做法，但并非所有大模型都这么做（GLM、Kimi、Qwen3.6 等有各自的取舍）。


4.采样 / argmax：logits → 下一个 token

  • 当模型处于训练阶段时， LM Head 之后直接计算 cross_entropy
  • 模型处于推理阶段时， LM Head 之后进行采样 / argmax

LM Head 输出 6400 个分数，但模型只需要输出一个 token，argmax / 采样就是“从 6400 个分数里选一个”的规则。

argmax：直接选取分数最高的

每次输出完全一样。 适合 benchmark、可复现场景。


采样：按概率随机选取

Step1：softmax 变成概率

Step2：按概率随机抽选

每次输出可能不同。 适合日常对话、创意生成。

可以通过设置temperature来控制随机程度


MiniMind 使用：

MiniMind 的推理默认使用采样（Sampling），主要采用Top-p采样，并结合温度（temperature）参数来控制生成的随机性。

参数 默认值 作用
temperature 0.7 或 0.85 控制随机性。值越低，分布越尖锐，越接近 argmax；值越高，分布越平缓，随机性越强。
top_p 0.9 或 0.95 核采样（Nucleus Sampling）。模型只从累积概率达到 top_p 的最小候选 token 集合中采样，动态调整候选集大小，避免生成不合理的词。

在 MiniMind 的 generate 方法中，可以通过设置 do_sample=False 来强制模型使用贪心解码，即每个步骤都直接选择概率最高的 token。

6.完整链路

阶段 组件 输入 输出
1 Tokenizer Encoder 文本 token ids (B, S)
2 Embedding token ids 向量 (B, S, D)
3 Transformer Block × N 向量 向量
4 LM Head 向量 logits (B, S, vocab)
5 采样/argmax logits 下一个 token id
6 Tokenizer Decoder token ids 文本
