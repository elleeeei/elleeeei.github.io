01 预训练（Pre-training）

1.为什么需要预训练

问题： 随机初始化的模型，输出完全是乱码

预训练的目标：让模型学会“语言的统计规律”。给定上文，下一个 token 最可能是什么。

预训练之后：


2.怎样进行预训练

数据格式

MiniMind 的预训练数据是纯文本 JSONL，每行一个对象：

关键：只有文本，没有标签。 标签是训练时自动从文本里构造的。


训练任务：Next Token Prediction

一段文本 tokenize 后：

输入和目标：目标就是输入往左移一位。

每个位置都在做“给定前面的 token，预测下一个 token”。


损失函数：交叉熵

每个位置，LM Head 输出 6400 个 logits：

整个序列所有位置的 loss 取平均：

$$L_{pretrain}=-\frac{1}{S} \sum_{i=1}^S logP(target_i|context_{＜i})$$

训练时所有位置都算 loss，因为每个位置的“下一个 token”都是已知的。


训练循环


关键超参数

参数 典型值 作用
learning_rate 5e-4 ~ 3e-4 预训练学习率较大
batch_size 32（视显存） 一次处理多少条
max_seq_len 340 ~ 512 截断长度
epochs 1 ~ 2 预训练通常 1 个 epoch 足够

学习率调度： warmup + 余弦衰减，从 0 升到最大值，再慢慢降到最小值的 1/10。


预训练之后的模型

但不会对话。 对话能力是 SFT 阶段教的。



02 监督微调（Supervised Fine-Tuning）

1.为什么需要监督微调

问题： 预训练模型只会“续写”，不会“对话”

SFT 的目标：教会模型“对话格式”。看到问题，给出回答。


2.怎样进行监督微调

数据格式：多轮对话

SFT 数据是结构化对话，和预训练的纯文本完全不同：

关键：有 role（谁说的）和 content（说了什么）。


Chat Template：把 JSON 变成模型能读的文本

模型不能直接读 JSON，需要先把对话拼成一段文本。这个过程叫 apply_chat_template：

<|im_start|> 和 <|im_end|> 是特殊 token，标记每条消息的开始和结束。

MiniMind 在 SFT 阶段还会做一些数据增强：

增强 作用
随机插入 system prompt 让模型见过“有 system”和“没有 system”两种情况
随机移除空的 <think> 标签 提升模型对“思考开关”的鲁棒性

Loss Mask：SFT 的核心

SFT 和预训练最本质的区别，就在 Loss Mask。

SFT 数据里，user 说的话是给定的输入，不是模型要生成的内容。模型只应该学习 assistant 的回答。

做法： 把所有非 assistant 的 token 的 label 设为 -100。

-100 是 PyTorch CrossEntropyLoss 的默认 ignore_index，梯度会被置零。

效果： 模型不会因为“没预测对 user 的问题”而被惩罚，只专注于学习“该回答什么”。

如果数据包含推理过程（reasoning_content），<think> 块也会被纳入 loss，让模型学会“先思考，再回答”。


损失函数

$$L_{SFT}=-\frac{1}{N_{assistant}} \sum_{i∈assistant} logP(token_i|context_{＜i})$$

求和只遍历 assistant 的位置，user 和 system 的位置被 -100 跳过了。


训练循环

和预训练几乎一样，唯一区别是 loss 调用时要传 ignore_index=-100：


关键超参数

参数 典型值 和预训练的区别
learning_rate 1e-5 ~ 5e-6 比预训练小 100 倍，精调而非粗调
epochs 2 ~ 3 比预训练多几轮
batch_size 16 ~ 32 视显存

为什么学习率小这么多： 模型已经有语言基础，SFT 只需要“微调行为”，不需要“重塑参数”。学习率太大会破坏预训练学到的知识。


SFT 之后的模型

但回答的质量、风格、安全性还没有经过偏好优化。



03 参数高效微调（Parameter-Efficient Fine-Tuning）

1.为什么需要参数高效微调

问题： 全参数 SFT 成本高，而且容易“灾难性遗忘”

  • 成本高： 64M 模型全参数微调需要更新全部参数，显存和计算都不便宜

  • 灾难性遗忘： 在医学数据上全参数微调，可能把通用对话能力“冲掉”

LoRA 的目标：用极少量可训练参数，适配新领域，同时保留基座的通用能力。


2.怎样进行参数高效微调

对于原始权重矩阵$W_0$，LoRA 冻结$W_0$，在旁边加一个低秩增量：

核心思想：低秩分解

$$W^{‘}=W_0+\Delta W=W_0+B×A$$

参数说明：

$A∈\mathbb{R}^{r×d}$：低秩矩阵，高斯初始化
$B∈ \mathbb{R}^{d×r}$：低秩矩阵，零初始化，保证训练开始时$\Delta W=0$
$r$：秩（MiniMind 默认 rank=16），远小于$d$

参数量对比：

  • 原始矩阵：768 × 768 ≈ 59 万参数
  • LoRA：768 × 16 + 16 × 768 ≈ 2.5 万参数

可训练参数只有原来的约 4%


注入位置

MiniMind 的 apply_lora 遍历模型，把 LoRA 适配器注入到 Attention 的 Q、O 投影层（以及维度匹配的线性层）。

MiniMind 的 apply_lora 按维度条件筛选：

条件：in_features == out_features（方形线性层）。

MiniMind 用了 GQA（n_kv_heads=4 < n_heads=8），K/V 的输出维度只有 384，不是方形，所以默认不注入。

前向传播时，原始路径和 LoRA 路径的输出相加：


训练时只更新 LoRA 参数

其余参数全部冻结，不计算梯度，不更新。


数据格式

和 SFT 完全一样：

只是数据内容换成领域特定数据（医学、法律、自我认知等）。


训练之后的 LoRA

得到一个很小的 LoRA 权重文件。推理时可以：

  • 合并式（静态融合）： $W^{‘}=W_0+B×A$，得到一个完整的领域模型，合并后，推理时没有额外的计算开销，和原始模型完全一样
  • 分离式（动态加载）： 基座 + LoRA 权重一起使用，不改变基座本身，推理时动态地将 LoRA 路径的输出加到原始输出上，方便快速切换不同的 LoRA 模块



04 强化学习（Reinforcement Learning）

1.为什么需要进行强化学习

问题： SFT 只教了模型“该怎么说话”，没教它“哪种说法更好”

强化学习的目标：用“偏好信号”或“奖励信号”进一步优化模型的输出，让它更符合人类期望。

MiniMind 涉及两类反馈信号：

类型 反馈来源 代表算法
RLHF 人类偏好 DPO
RLAIF AI/规则反馈 GRPO、CISPO

2.怎样进行强化学习

DPO（Direct Preference Optimization）——RLHF 路线

核心思想：不需要奖励模型，直接用偏好对训练

数据格式： 成对的 chosen / rejected

损失函数：

$$L_{DPO}=-log\sigma(\beta[log\frac{\pi _{\theta}(y_w|x)}{\pi _{ref}(y_w|x)}-log\frac{\pi _{\theta}(y_l|x)}{\pi _{ref}(y_l|x)}])$$

参数说明：

$\pi_{\theta}$：当前训练的模型
$\pi_{ref}$：SFT 后的参考模型，全程冻结
$y_w$：chosen
$y_l$：rejected
$\beta$：控制偏离参考模型的程度，默认 0.1

直觉： 让模型提高 chosen 的相对概率，降低 rejected 的相对概率，同时用参考模型防止跑偏。

DPO 是离线训练： 偏好数据是静态的，不需要在线采样，也不需要奖励模型。


GRPO / CISPO——RLAIF 路线

和 DPO 的区别：GRPO 是在线的，模型自己生成回答，再用奖励信号打分

流程：

  • 给定 prompt，模型 rollout 生成一组（G 个）回答
  • 奖励模型/规则给每个回答打分 R_i
  • 计算组内相对优势：$A_i = \frac{R_i - mean(R_{group})}{std(R_{group})}$
  • 用策略梯度更新模型：高于组内平均的回答被鼓励，低于的被抑制

GRPO 损失：

$$L_{GRPO}=-\mathbb{E}[min(r_tA_t,clip(r_t,1-\epsilon,1+\epsilon)A_t)-\beta KL_t]$$

CISPO 是 GRPO 的 loss 变体，把策略项从 min(r·A, clip(r)·A) 改写成 min(r, ε_max) · A · log π，解决“ratio 被 clip 后梯度流被截断”的问题。

只需在相应代码中设置 loss_type="cispo" 即可切换。


三种 RL 算法对比

算法 反馈来源 是否需要奖励模型 是否在线采样 数据格式
DPO 人类偏好 ❌ 不需要 ❌ 离线 chosen / rejected 对
GRPO AI/规则 ✅ 需要 ✅ 在线 rollout prompt + 空 assistant
CISPO AI/规则 ✅ 需要 ✅ 在线 rollout 同 GRPO（loss 变体）

RL 之后的模型

模型不仅“会回答”，而且回答更符合偏好：

  • DPO：更倾向于 chosen 风格的回答；
  • GRPO/CISPO：在可验证任务（数学、工具调用）上，正确率更高。

代价：RL 可能带来“对齐税”——特定能力提升，但通用能力可能略有下降。
